# Adjudicate role-play Turns through DM Tools

At the initial Director Point, role-play schedules DM with the sole Instruction `开始演出。`; initial scene and cast material remain in its system prompt. Later top-level DM adjudication begins with a DM Turn that receives the complete preceding ordinary Character Turn Projection. It produces one or more successful `voice_over` calls that each cover every ordinary Character and finishes by successfully calling `recommend_next_character` or `end_performance`; either success immediately concludes the Turn. A recommendation carries the selected Character and an Agent-observable reason that has no scheduling semantics. When a top-level DM Turn ends before satisfying this contract, Theater may open another DM Turn up to three DM Turns in total; the repair Instruction states why validation failed and does not repeat the Character Turn Projection already present in the DM Character Session. Successful voice-overs from earlier attempts remain facts and count toward the same adjudication; repair Turns add only what is missing. Three failures stop the Theater Main Loop. When a Character is selected, its Instruction contains, in durable Turn order, public assistant text from other ordinary Characters and successful DM projections since its previous settled top-level Turn, or since Performance creation for its first Turn. Public text is XML-escaped and rendered as `<character_message character="id">content</character_message>`; `think` and `perceive_or_recall` calls are rendered as parameter-free `<character_tool character="id" name="tool" />` elements while their parameters and results remain private to the source Character and DM. Visible voice-over content is retained unchanged, including empty content, and each successful `warn` is broadcast to every ordinary Character as an escaped `<dm_warning>` element. Recommendation reasons are excluded, and nothing is appended to an inactive Character Session. `perceive_or_recall` keeps the outer Character ReAct loop open and may be called once in that outer Turn; a second call returns an error Tool Result without opening a nested Turn. Its first call opens another nested DM Turn when the preceding attempt produced no `perception_result`, tries at most three DM Turns in total, and cancels the outer Character Turn so the Theater Main Loop stops after all three fail.

Role-play keeps each Character's Tool catalog static. Ordinary Characters receive `think` and `perceive_or_recall`; `think({ thought })` succeeds with an empty response and does not add call-count or Turn-kind restrictions. Top-level DM Turns accept `voice_over`, `warn`, `recommend_next_character`, and `end_performance`; nested DM Turns accept `perception_result`. DM Tools validate calls against Theater's current Turn kind, and a wrong-mode call returns an error Tool Result without producing a fact. The initial implementation has no `d20`, auxiliary Tool category, or dynamic Tool registration.

The Tool shapes are limited to `think({ thought }) -> null`, `perceive_or_recall({ content }) -> { content }`, `perception_result({ content })`, `voice_over({ segments: [{ visibleTo, content }] })`, `warn({ target, reason })`, `recommend_next_character({ character, reason })`, and `end_performance({})`. A successful `perception_result` concludes a nested DM Turn; a successful recommendation or end concludes a top-level DM Turn. Voice-over visibility must cover every ordinary Character, its content may be empty, and warning and recommendation targets must name ordinary Characters. No die or generic metadata field is included.

Role-play projects an ordinary Character Turn to DM as natural-language fragments in original order, without a JSON envelope or an instruction heading. Direct assistant text uses `[character尝试说话/行动]\ncontent`; a perception call uses `【character】询问：content`; its result uses `[character感知/回忆结果]\ncontent`. The projection excludes the incoming Instruction, reasoning, call IDs, execution boundaries, and display metadata. A nested DM Turn receives the prefix through the current perception call, while top-level DM adjudication receives the completed Turn.
