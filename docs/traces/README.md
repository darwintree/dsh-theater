# Traces

`docs/traces/` preserves original discussion and implementation records for
historical lookup. A trace describes what was considered or decided when it was
written.

Traces are archival, not normative, and need not match the current code,
architecture, or terminology. Keep existing traces unchanged as the system
evolves. Use `CONTEXT.md` for current vocabulary, accepted non-superseded ADRs
for architectural decisions, and current package documentation and code for
behavior.
